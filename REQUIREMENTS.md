# Requirements and verification map

Code references are repository-relative. Automated evidence is repeatable through README commands; timing evidence is recorded separately in PERFORMANCE.md and `evidence/*.json`.

| Mandatory requirement | Implementation | Verification |
|---|---|---|
| 1. Create/join by code or invite | `Engine.join` in `server/engine.ts`; URL `?room=` and entry UI in `src/main.tsx` | Room protocol tests; browser invite and invalid-code workflows |
| 2. Synchronized play/pause/seek | Authoritative anchor/version/revision in engine; player synchronizer in frontend | Protocol ordering and actual two-browser HTML5 playback tests; both benchmarks |
| 3. Recommendations/categories/filters/fuzzy search | 26 labeled entries in `server/catalog.ts`; Fuse.js and genre/mood/playable filters in frontend | Browser typo search and preference-reason checks; seeded SQLite catalog; evaluator walkthrough |
| 4. Reactions/chat/playlists/polls/host transfer | Validated engine command union and complete-state broadcasts; functional audience/activity tabs | Engine activity tests and browser workflow for every listed feature |
| 5. Automatic drift detection/correction | `expectedPosition`/`correction` in `shared/types.ts`; 100 ms checks and bounded rates/seeks in frontend | Drift math tests; browser injected-drift test; actual playback benchmark |
| 6. Late joins/reconnect/concurrency | Complete join state; secure resume tokens, grace timers, operation deduplication, monotonic versions, media-revision checks | Unit tests for late joins, reconnect, forged/duplicate identities, serialized commands, stale events and dedup; real socket reconnect; browser offline/online and late-join tests |
| 7. At least 10 concurrent users/room | 32-participant capacity; bounded room state | Ten-socket integration test, ten-client socket benchmark, browser benchmark report (context mode disclosed) |
| 8. ≤250 ms p95 local-network control propagation target | Immediate server validation, persistence and room broadcast | Actual localhost reports in PERFORMANCE.md; **real physical LAN remains unverified** |
| 9. ≤500 ms corrected drift target | Large-error seeks, modest ±5% rates, paused correction and readiness gating | Math test, multi-browser injected drift and measured `currentTime` benchmark; conditions/limitations in PERFORMANCE.md |
| 10. Document actual latency/conditions/failures | `scripts/benchmark.ts`, `scripts/browser-benchmark.ts`; explicit delivery/application/drift methodology | Saved raw JSON, PERFORMANCE.md, README troubleshooting and environment-attempt notes |

The companion follows service pages through each viewer's own authorized account. It does not embed or relay subscription video and does not access credentials, cookies or DRM material. Audius is an artist-published catalog, not an all-songs source; Navidrome serves a library supplied by the operator.
