# Browser environment notes

- Normal ten-isolated-context benchmark on 2026-10-12 stalled after four ready contexts as Windows free commit fell to roughly 340 MiB. The attempt was stopped; no results were claimed.
- Experimental Chromium single-process mode could not create a second isolated context and exited. This mode was removed from the final command.
- The repeatable low-memory option uses one shared browser context with separate pages/sessionStorage identities and process-per-site rendering. The application uses no cookies or localStorage for identity. Normal isolated-context mode remains the default; the report states which mode was used.
- A first shared-context attempt reached ten ready players but its Node benchmark controller exhausted Windows commit during sampling. The final command bounds the Node heap/semi-space, uses cinema layout in low-memory mode, and the generated video was reduced from approximately 12.3 MiB to 2.8 MiB.
- The first completed ten-player report is retained as `browser-benchmark-initial.json`. It had all 270 delivery and 300 drift samples, but 54 application-timing samples were absent because periodic diagnostics replaced the latest operation marker. The recorder was corrected to retain the pending playback operation; player `seeked`/`playing` events also trigger immediate synchronization. Final evidence is `browser-benchmark.json`.
- After the machine's memory pressure eased, the preferred **ten isolated browser contexts** completed successfully. Final normal-mode report: 270 delivery samples (7.53 ms p95), 270 application samples (28.45 ms p95), 300 drift samples (66.86 ms maximum), no missing samples or failures. The completed shared-context fallback report is retained separately.
- Unit/build tooling initially also exhausted the commit budget when concurrent Vite/tsx watchers ran. Checks passed after stopping this project's watchers and using the compiled single-process Node server. Other user processes were left alone.
